# Assess collection compatibility independently of exact harness releases

The user chose automatic collection on previously untested harness releases when
the required collection operations and known content formats pass checks. Exact
release numbers remain provenance and acceptance evidence; they do not by
themselves determine collection eligibility. This avoids requiring an app update
or harness downgrade for every compatible release, while actual format or
operation incompatibilities remain visible and can disable the affected work.
Runtime checks do not establish full coverage or confer acceptance evidence on
an untested environment.

Native CLI, T3, and local sessions in the official Codex GUI and Claude GUI Code
tab must work concurrently. The GUI apps are required support targets rather
than deferred additions. Ordinary Claude Chat, Cowork, cloud execution, and SSH
execution remain outside this release's scope. Select a parser by provider source
format and collection route;
the agent host is provenance rather than a separate parser requirement. Preserve
one canonical authority and stable native identities when routes overlap.

When a changed format prevents analysis of any required content type, keep
unaffected content and routes operating, show the missing scope, and send one
masked user notification per confirmed incident when notifications are enabled.
This is collection degradation even when other content types still work. An
untested release, extra optional fields, or intentionally unsupported content
alone does not establish a format failure.

Recovery of previously skipped content uses available original history within
the existing seven-day analysis window and the bounded encrypted queue. The
user does not require backward source compatibility beyond that window or an
additional long-lived raw-content archive. Reading progress must remain
distinguishable from analyzed coverage so a parser update can recover eligible
omissions without recreating already processed occurrences. This limit applies
to source analysis; retained inventory remains governed by
[ADR 0002](0002-retain-encrypted-values.md).

Connection verification is remembered across app restarts and compatible harness
upgrades when its owned registration and configuration remain applicable.
Reassess compatibility automatically and repeat the synthetic challenge when
the route needs repair or the saved proof no longer applies. Provider-owned
hook trust and recent collection activity remain separate facts.
