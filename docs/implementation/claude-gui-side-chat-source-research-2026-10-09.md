# Claude Desktop Code side-chat source research

Research date: 2026-10-09. This is a source-contract investigation, not acceptance
evidence or an implemented collector. No GUI automation, private app network or
database inspection, provider setting changes, plugin installation or new provider
turns were used for this research.

The genuine R2 observation used official Desktop `2.31226.0` with embedded Claude
Code `2.1.293`. The operator confirmed a visible side-chat prompt and response.
The main/child fixture committed fifteen encrypted occurrences with all required
types; the selected side markers were absent from the ordinary hook observations
and original selected transcripts. Three complete `MessageDisplay` groups belonged
to main content. Desktop eligibility remains disabled until a supported live
side-prompt/response route, native identities and unavailable-history accounting
are established. Main-content success does not settle that gate.

## Official contracts and their limits

Desktop side chats use a snapshot of main-thread context without adding their
content to the main conversation. Anthropic says Desktop does not save them to
disk. Its embedded Code producer updates separately from the standalone CLI;
`/status` reports the embedded version. Disk-history enumeration cannot provide
content that the producer never persists. [Desktop documentation](https://code.claude.com/docs/en/desktop)

The current hook reference says internal `/btw` agents fire `SubagentStop`, whose
payload includes `agent_id`, `agent_type`, `agent_transcript_path` and
`last_assistant_message`. An internal agent's type can be empty; an omitted,
empty or wildcard matcher includes it. The owned R2 registration already omitted
that matcher. The docs do not explicitly promise side-chat `UserPromptSubmit`
delivery. Common `prompt_id` identifies a submitted prompt, but its presence in
this Desktop side path remains unmeasured. `MessageDisplay` carries assistant
text only. Its message IDs explicitly cannot be correlated with transcript API
message IDs. [Hook reference](https://code.claude.com/docs/en/hooks)

The changelog introduced SubagentStop native agent/path fields in `2.0.42`, final
text in `2.1.47`, and `MessageDisplay` in `2.1.152`. Its `2.1.275` fix concerned
specific matchers firing for empty agent types. `2.1.285` changed Desktop remote
`/btw` context visibility, and `2.1.294` improved prompt-type Stop evaluation.
These entries do not establish a newer Desktop side-prompt/history collection
contract or explain the measured missing events.
[Official changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

Agent SDK history helpers list sessions and read messages on disk. Its public
hook input types expose the same agent/path/final fields; they do not document a
passive attachment to an existing Desktop side chat's in-memory conversation.
Resuming or forking through the SDK would create agent activity and cannot replace
passive collection. [SDK session documentation](https://code.claude.com/docs/en/agent-sdk/sessions),
[official SDK types](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/types.py)

## Supported candidate for a bounded next test

Claude Mods support Desktop Code from embedded `2.1.286`, so the measured
`2.1.293` meets that prerequisite. The supported `/plugin-types` command writes
the exact installed producer's declarations, while `claude plugin validate`
checks a mod's declared events and calls without running it. The published type
copy can be older than the installed producer. No plugin was installed here.
[Mods overview](https://code.claude.com/docs/en/plugins/mods/overview)

The mod reference offers `prompt.submit`, `turn.start`, `turn.step`,
`turn.complete`, `session.append`, and classic hook events. Desktop render sites
include `UserMessage` and `AssistantMessage`, with `requestId` described as the
message ID. `$.session.id()` supplies session identity. These are supported
extension points, but the reference does not promise that side-chat panes pass
through them or that render IDs match canonical transcript identities.
[Mods reference](https://code.claude.com/docs/en/plugins/mods/reference)

The public declarations currently identify themselves as generated by `2.1.277`,
older than both the measured producer and current Desktop prerequisite. Their
session-message view lacks message UUIDs and always reads the main transcript,
even from an agent loop. Render request IDs identify drawing instances. These
facts make exact-version declarations and genuine identity tests necessary before
choosing a canonical live authority.
[Official mod declarations](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts)

A possible next experiment is one owned pass-through mod, loaded through ordinary
native controls for a fresh fake-only project. Filter by the selected native
session before retaining observations. Observe the candidate prompt, turn,
classic-SubagentStop and user/assistant render events while the operator posts
one side prompt. Return events and streamed results unchanged; create no turns,
messages or agents. The documented pass-through form preserves native behavior.
[Mod event guide](https://code.claude.com/docs/en/plugins/mods/events)

The test must establish side-prompt and final coverage, native session/agent/item
identity, repeated-render deduplication, exact side attribution and encrypted
commitment. Inspect `last_assistant_message` as well as display deltas: the R2
controlled hook journal's marker extraction alone did not inspect that final-text
field. Record unavailable cold history explicitly. Retain only controlled counts
and encrypted selected-source evidence, with no raw source archive. This is a
proposed experiment, not a claimed route; success must precede Desktop enablement.
