# Milestone 1 review

Reviewed the app shell, compiled helper, core contracts, and offline test definitions against `SPEC.md`, `IMPLEMENTATION_PLAN.md`, and all four ADRs. No milestone-1 contract finding remains open. The user authorized development to continue with macOS 14 runtime and hardware without Touch ID deferred until before release; those measured feasibility checks remain unverified.

The core distinguishes exact-value fingerprints, canonical source items, occurrence ranges, detector evidence, occurrence review, obsolete classification, and retention. Fixtures cover hook/history arrival order, distinct identical outputs, repeated ranges, merged rule evidence, ambiguous-to-strong eligibility, reversible review, historical summaries, deletion receipts, appended content, obsolete markers, replacement identities, and forgetting. Monitoring, queue activity, and coverage remain independent. These are in-memory contracts using synthetic fingerprint stand-ins, not cryptographic or durable-storage evidence.

The review found and resolved three issues:

- The helper parsed and reserialized entire events synchronously. Valid 8,000,019-byte structured inputs took 221 and 279 ms with an unavailable endpoint. It now sends bounded raw event bytes inside a versioned binary frame, validates the receiver's user before reading stdin, and leaves event validation to the app. Six independently measured deliveries to a disposable listener took 84–103 ms including process startup, with verbatim event bytes and an acknowledgement. The helper owner separately observed a 568 ms initial run. Startup and scheduling were not measured separately, so these results do not establish a guaranteed total wall-clock bound.
- Retained obsolete appearances lacked a stored classification. [`Occurrence`](../../Sources/SpillcheckCore/DetectionContracts.swift) now stores classification separately from review and confidence, and summary counts include retained and metadata-only obsolete appearances. Forgetting the marker preserves prior appearance labels.
- Reanalyzing a retained obsolete appearance after forgetting could create an alert. [`InventoryLedger`](../../Sources/SpillcheckCore/Inventory.swift) now checks the stored appearance classification before issuing an existing-occurrence alert. [`retainedObsoleteReanalysisAfterForgetStaysSilentButNewItemAlerts`](../../Tests/SpillcheckCoreTests/InventoryTests.swift) verifies that detector-version reanalysis stays silent while a genuinely new item in the same session alerts normally.

Canonical coordinates are explicitly immutable. Append-only richer content can add ranges without resurrecting deleted ones. Rewritten content and shifted offsets require verified adapter mapping; an item revision alone does not prove that mapping. Unresolved cases must become visible coverage gaps when the adapters are implemented.

The core owner reports 34 passing Swift tests; the helper owner reports 13 passing transport tests. This review inspected those definitions and the targeted fixes without duplicating the full suites. Native lifecycle verification belongs to the app's recorded gate evidence. Durable transactions, crash recovery, encrypted storage inspection, installed adapters, OS notification delivery, and release packaging remain later milestone checks.
