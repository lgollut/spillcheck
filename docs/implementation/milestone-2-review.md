# Milestone 2 review

This review covers protected ingestion, storage transactions, keys, deletion, and runtime cancellation. It does not require installed agent adapters or the production detector, which belong to milestone 3. The user deferred macOS 14 runtime and hardware without Touch ID until before release. Encryption and authenticated private-key use remain required now.

The focused implementation review is complete. No remaining milestone-2 implementation blocker was found in the reviewed storage, protection, transport, and runtime paths after the fixes below. This is a source and evidence review, not a claim that agent adapters or the final viewing workflow are complete.

The storage owner reports `swift test --filter StorageTests` passed 15 test declarations and 18 executed cases, including four parameterized child-process crash cases. The protection owner reports all 21 focused protection tests passed. The final owner-run `swift test` exited 0 with 77 tests in six suites at 2026-10-07 22:29:59 UTC. Swift Testing's reported total counts the four crash arguments under one test declaration. I inspected the tests and assertions without duplicating these suites.

The actual signed [production protection report](production-vault-interactive.json) was independently reviewed. All 16 checks are true, with interactive authorization requested and passed. The probe writes a disposable synthetic source, removes it before revealing, wraps through the exported LocalAuthentication public key using Security.framework, and verifies exact authenticated unwrapping. It checks private-operation denial on the same production viewing session after Mask. This establishes real framework compatibility on the tested environment. It does not establish the deferred environment matrix or an authentication method for every authorization event.

The actual [production ingestion report](production-ingestion.json) records an encrypted durable insertion before helper return in 35.8 ms including startup. Paused delivery took 10.2 ms without insertion. After quit, the process and socket were absent, delivery returned in 19.2 ms, and the already-durable queue item remained. Database, WAL, and SHM files were mode 0600 and contained no synthetic plaintext marker. Restart reused the existing keys and pending queue. With the window closed, capture still committed and reopening preserved the PID. The recorded 207.1 ms for that case includes process inspection and is not a helper delivery timing.

The review found and verified these corrections:

- `ProtectedStore.probe` counts an existing protection manifest as protected state. Fresh manifest and empty ledger initialization now share one transaction. An existing manifest with a missing ledger fails as corrupt protected state, including after only an obsolete marker remains. The regression verifies that opening does not recreate the missing ledger.
- Deleting a value consumes linked retry captures and records a protected coverage gap in the same transaction. The mixed-content regression includes another value in the discarded capture, so this loss is visible.
- Bounded queue-age maintenance runs while idle or paused. It consumes expired rows and records a gap atomically. `AppRuntime.refresh` calls it once per refresh, with a default maximum of 256 rows per pass. The regression also rejects maintenance after store closure.
- Late throwing authorization and decryption callbacks now perform the same generation check and final key deauthorization as successful callbacks. A new reveal waits for the retiring operation and cleanup. The regression holds each throwing framework callback across invalidation and verifies that the subsequent reveal stays authorized.
- The subprocess acceptance driver now encrypts the replacement value itself. Its previous replacement fixture encrypted the original value while using the replacement fingerprint.

The acceptance cases below use fresh disposable stores, synthetic content, and child processes. The signed probe's source fixture is removed before its retained-value reveal and protected-file check. It is never a real agent history.

Raw helper envelopes do not automatically establish canonical source identity. If the receiver cannot prove identity before ACK, it must preserve captures conservatively rather than suppressing identical raw payloads. Canonical source/range receipts own occurrence deduplication after normalization. Queue uniqueness claims apply only to inputs with stable ingestion identities.

The milestone-1 immutable-coordinate contract remains in force. Appended ranges can be new work. Rewritten or shifted content needs a verified adapter mapping; an item revision alone cannot supply it. Storage tests should not claim generic reconciliation of those revisions.

The crash test uses a file handshake at each failpoint, stops the child, and sends SIGKILL from the parent. A new process inspects and resumes the same store. Before processing commit, it observes a retained queue item and no inventory, occurrence, receipt, outbox, or checkpoint. After processing commit, it observes queue removal, one occurrence and alert decision, and checkpoint offset 100. Replay preserves the opaque notification identifier. A separate-process scenario verifies deletion suppression, metadata-only obsolete appended appearances, a replacement value, forgotten markers, and a genuinely new item.

Helper-side oversize input is not silently invisible to an active receiver. The helper connects to the same-user app endpoint before reading stdin. Local rejection closes that accepted connection; the receiver's incomplete-frame path records `captureRejected`. The actual production ingestion report confirms that an input over 8 MiB left the queue unchanged, persisted the rejection gap, and returned only the no-effect response with empty stderr in 102.4 ms including startup. The absent-app and intentional-pause cases do not establish an exact count of missed hook invocations.

Inspection of protected files establishes absence of the synthetic markers tested; it is not a forensic erasure claim. Deletion checks remove active payload references and prevent old source receipts from recreating them. Key-loss tests establish explicit recovery errors and preservation, not recovery of unavailable private keys. Production detector processing, history checkpoints from real adapters, notifications, and final user-facing recovery are gates of later milestones.
