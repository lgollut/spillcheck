# spillcheck

## 0.2.0

### Minor Changes

- 695a994: Read Claude subagents using their own native session identities and route child tool hooks to their exact transcript. Continue reading complete messages when a bounded read stops before an unfinished transcript line, recognize observed normal-mode control records, and recover affected saved cursors without duplicating existing occurrences. Retain child source selections for bounded retries without mistaking a successful parent read for child recovery.
  
  Add an explicit Settings opt-in for saved local Claude Desktop Code conversations, preserving existing defaults, profiles and connection proof. Show shared-profile collection as provider/profile transport evidence without attributing it to an originating app. Desktop side questions remain unsupported.
- 695a994: Collect prompts, final replies and hook-exposed tool results for explicitly selected Codex sessions, with encrypted duplicate suppression and visible identity conflicts. Select the hook or native-history route before admission and preserve it through replay; keep unrelated native sessions collecting. Label hook timestamps as observation times and explain unavailable intermediate replies, interruptions and storage limits. Automatic desktop side-chat enrollment and genuine side-tool acceptance remain pending.
- 695a994: Collect returned text from native Codex web-search items, with bounded parsing and recoverable coverage gaps. Report shared Codex profile activity without attributing it to an unverified CLI or app host.
  
  Allow explicit opt-in to partial Codex desktop collection from retained native conversations. Preserve existing profile authorization and show the remaining side-chat and encrypted child-input limitations.
  
  Keep missing native subagent instructions visible when a complete public read omits them, without treating inherited prompts as the subagent's original input.
  
  Bind prepared Codex resume commands to the finding's saved profile and home. Refresh commands when that binding changes and reject unmatched profiles instead of using the terminal's default home.
- 695a994: Show collection storage usage and remaining capacity before conversation and Codex hook records reach their limits. Explain capacity rejection separately from delivery failure, preserve duplicate suppression across lowered limits, and keep capacity warnings separate from missing-content reports.
- 662cfe6: Coverage gaps are now grouped by cause instead of listing every source and
  catch-up attempt separately. Each issue shows how many sources and records it
  affects, and one button retries all of its sources; each source can still be
  retried from the issue's details. Reads still in progress and content excluded
  from text analysis by design are summarized below the list.
- 94de276: Decide once per value instead of reviewing each appearance. A value now asks "Does this need rotating?" and offers Test or dev only, Not a secret, Needs rotation, or, from the menu, Real, but keep it. The answer covers every appearance of that exact value, including later ones: a value you dismissed no longer comes back for review when an agent prints it again, and only its count of new appearances grows. A value that needs rotation waits under To rotate and still alerts in new conversations until you mark it rotated or revoked. After a decision, the next value to review opens. Removing a value's retained content keeps your decision. Earlier reviews carry over: a value with an appearance you confirmed as a secret needs rotation, and one whose appearances you all marked as not a secret stays dismissed.
- 8247eaa: When a value is revealed, Spillcheck now reads what its content says about when it stops working, and says so next to the value: the token's own expiry, a signed link's end date, an expiry field printed next to it (such as a session's `expiresAt`), or a GitHub download link, which GitHub says expires on its own. When that date has passed, or a GitHub download link was last seen more than a day ago, the value is tagged "Expired" or "Probably expired", the review explains why, and No longer works (X) becomes the highlighted answer. A date printed next to a value is only what the output said at the time, since a session can be extended each time it is used, so Spillcheck suggests the answer and never decides it for you.
- bcf15c1: Go through values one at a time in Focus. Start it with Focus or F from To review or To rotate, or with "Go through one by one" after selecting several values. Each value shows with its evidence; T, N and R decide, D marks a value rotated, the arrows move back and forth, and Escape returns to the inbox. A session ends with a summary of what you decided and, after a review, offers to continue with the values to rotate. You can also Command- or Shift-click values to select several and decide them together, in one step that Undo takes back.
- 639b516: Collect Claude Code and Codex sessions from releases Spillcheck has not been tested
  with, as long as their content can still be read, instead of stopping at an
  unsupported version. CLI and T3 sessions in the same home are collected side by
  side, and Coverage shows each host separately. Desktop app collection stays off.
  
  When some content can't be read, the rest keeps being analyzed: Coverage reports
  partial coverage, unread content is retried for up to seven days, and required
  content that stops being collected triggers a masked notification. Prompts typed while Claude
  is still working are now checked too.
- 695a994: Report seven-day coverage and recovery accurately, retain historical losses separately from restored reads, and add scoped history retry and content-free diagnostics. Recognize current Codex tool output formats, retry unavailable Claude history, and prevent oversized records from stalling catch-up.
  
  Preserve exact key identities through interrupted vault setup and incomplete cleanup, and resume setup with them on the next launch instead of stopping or creating replacement keys. Require a matching committed store manifest before completing startup. Allow diagnostic export when the vault cannot open, and distinguish unavailable storage from a paused or empty inventory.
- 7ce426b: Review values in an inbox. The list is split into To review, To rotate and Done, each with its count. Values that appeared since you last looked have an unread dot and come first, which replaces the "While you were away" box. The detail leads with the evidence: what was found and why, the value inside the context where it appeared, then every conversation that printed it. Decide with the buttons or the T, N and R keys; the next value then opens, and Undo, or Command-Z, takes the decision back. A value to rotate offers Mark rotated, D, and Mark revoked once you've changed it at its service. Opening and Resume in Terminal now sit in each conversation's menu. Entries are numbered #12 instead of L-12, and matches are described as Known format, Unsure match or Generic pattern.
- d084eb1: Review asks one question with two outcomes. "Does this need rotating?" Needs rotation moves the value to To rotate. Every other answer moves it to Done, where later appearances stay quiet, and the bar now says so. The other answers are reasons: Not a secret, Test or dev only, and, from the menu, No longer works (expired, revoked or rotated) and Real, kept as is. No longer works also has its own key, X. To rotate has one button, Mark rotated or revoked (D), instead of two. Rotated and revoked values show as "No longer works" in Done, Accepted risk shows as "Real, kept as is", and values in Done go Back to review instead of changing their decision.
- 509bb01: Add a setup assistant that opens on first launch. It explains how Spillcheck
  works, finds Codex and Claude Code, adds hooks to the agents you choose, and
  confirms each connection with one test session. It then sets alerts and launch
  at login. Settings › General › Run setup again reopens it.
  
  Coverage is the home screen while the inventory is empty, and it shows clearly
  while the last 7 days are being read. Activity indicators no longer flicker.
  Notification and launch-at-login settings update when you return to the app.
  
  Fix detection that could stall while stopping a scanner, which left new
  sessions unscanned. Reading history now ends once history is read, even while
  agents stay active.
- 8f84877: Unlock once to see every value with its context. While unlocked, each value you select shows right away, with the excerpt and conversation of its appearance, so there's no Reveal to click for each value. Hide values masks them without locking, and they stay hidden while you move between values until you show them again or the session ends. Lock, 5 idle minutes, closing the window and sleep still lock the session.
- 473918d: Spillcheck now uses its own bundle identifier, `com.spillcheck.app`, instead of `com.leakret.app`. macOS treats it as a new app, so an existing installation can't open its vault. Remove the agent connections in the old version, then move `~/Library/Application Support/Spillcheck` aside and set Spillcheck up again. If the old version won't open, delete the Claude Code and Codex hook entries whose status message starts with "Spillcheck hook" or "Leakret hook" by hand, because the new version can't recognize them. Notification permission, launch at login and onboarding start fresh; remove the old Spillcheck entry from Login Items in System Settings.
- a2b0e2e: Show which file a tool output came from. When an agent printed a value by reading a file, such as `sed` on a test fixture or `cat` on `.env.local`, the appearance now names that file above its excerpt, with the program or tool that read it. Output that didn't come from a file names the program instead, such as `printenv`. Spillcheck keeps only the tool, the program and the file paths with the appearance, never the command's other arguments, so removing a value's retained content can't leave a copy of it inside a stored command. Appearances found before this version have no stored file: while unlocked, Spillcheck looks it up in the agent's own history if that history still exists, and doesn't store it.
- 550b326: Unlock once, then reveal freely. Touch ID or your password now unlocks the inventory, the way a password manager does. While it's unlocked, Reveal shows a value, its excerpt and its source without asking again. The value stays revealed as you open its other appearances, and Hide or choosing another value only hides it again. Unlock and Lock sit at the bottom of the sidebar. The app still locks after 5 minutes idle, when the window closes, or when the Mac sleeps or locks.

### Patch Changes

- 744b471: Show which agent is catching up. While Spillcheck reads the last seven days of history, Coverage now marks the agent being read with a "Catching up" indicator in its own row, instead of a banner above the totals that didn't say which agent was working. A wave crosses that agent's days not read yet, and a day fills in as soon as content from it is analyzed. Each agent's seven days now form a single bar instead of a row of checkbox-like squares, and days before the agent was set up are striped.
- 7d9e310: Give each agent its own Settings page. Codex and Claude Code now appear under Agents in the Settings sidebar, with a dot when one needs attention. Each page shows the agent's status and next step first, then the connection test while one is pending, then its executable, profile folder and desktop support, which you edit in place with a Choose button instead of in a separate dialog. Changes take effect when you choose Apply, and the page says when the profile folder can't change because hooks are installed. Collection details and known limits now live only in Coverage, the connection steps are shorter, and buttons no longer end in an ellipsis or get cut off.
- 90bc181: Captures keep being analyzed while the screen is locked. macOS naps apps that have no visible window, and Spillcheck did not say it had work waiting, so while the Mac was locked it got almost no processor time: it finished nothing for minutes while agents kept adding captures, and a long absence could let queued captures reach their 24-hour limit. Spillcheck now tells macOS it is busy while monitoring is on and captures are waiting, and stops as soon as the queue is empty. The Mac can still go to sleep as usual.
- c224438: Fix collection stopping after a long history catch-up. Spillcheck kept the record of every capture that noted a gap until the vault's storage limit was reached, and then could not accept any new capture. It now keeps the most recent of these records, trims a vault that is already full when it opens, and keeps collecting.
- 1914878: The Coverage page and the menu bar no longer rebuild each agent's connection state several times per redraw. Building it filters every current coverage limitation, and with thousands of records this kept the main thread busy while the Coverage page was open.
- 5c35912: Spillcheck uses less processor time while it catches up. Recording or recovering a coverage gap prepared the same vault statements again for every location, and a catch-up settles thousands of locations at a time.
- 511a90f: A Claude conversation with more than 32 agents, most of them finished, no longer adds an "Unread history remains" coverage note several times a second. The note now appears only when an agent that isn't being followed changes or the agent list is too long to read, and at most once every five minutes.
- 016e37d: Spillcheck now checks the text that Claude Code attaches to a conversation: files you mention in a prompt, edited-file snippets, context added by hooks, hook errors, background task results and IDE diagnostics. These were reported as "Some content wasn't in a supported format" and left unchecked. File paths, hook commands and the duplicate copy that newer Claude Code versions save of each attachment are not checked.
- 82586db: Claude Code catch-up no longer gets stuck on a folder with more than about 125 transcripts, such as a busy session's subagents folder. It used to restart that folder on every pass, so catch-up never finished, kept a processor core busy and never reached the older history queued behind it.
- d05004e: Fix Claude history catch-up repeatedly rejecting large batches without saving progress. Read dense transcripts in smaller resumable batches and recognize permission-setting records from setup sessions so they no longer cause false format warnings.
- 216ba45: Spillcheck uses less processing time while it watches Claude conversations. It checked every conversation it had seen since it started four times a second, including each one's subagent folder, even when the conversation had been idle for hours, so the work grew the longer it ran. A conversation is still checked on every pass while it changes, and then less often as it stays unchanged, down to every 30 seconds. Any change, or a hook from that conversation, makes it current again.
- d29c1de: Claude tool and prompt events from long conversations are no longer reported as lost. Spillcheck matches each tool or prompt event to the conversation rows it has read, and remembers up to 2,048 such calls per conversation. Once a conversation passed that number, it kept the wrong ones, so most new calls were forgotten as soon as they were read. Their events were retried as if the conversation had not been saved yet, then reported as not analyzed, although their content had been analyzed. Spillcheck now remembers the most recent calls.
- 99e7bd0: Claude Code 2.1.306 and later save request logs and workflow journals in their transcripts. Spillcheck now recognizes them instead of reporting tens of thousands of "Some content wasn't in a supported format" records, which kept Claude coverage partial and the app busy. A request log larger than 1 MB is still reported, like any oversized record. A workflow agent's structured result is now checked as that agent's final response.
- ad5fbaf: Fix Spillcheck reading every Claude Code conversation again after the Mac restarts. It treated the disk's device number, which macOS can change at each startup, as part of a file's identity. After a restart it therefore reported each conversation as changed and read its history again. It now recognizes a conversation file by the file's own identity, and reports a change only when the file was really rewritten or replaced.
- 695a994: Retry a selected Claude transcript when its original file returns after a temporary absence. Clear only that source's availability warning after a bounded native-identity and readability check; preserve unrelated content, scanner and delivery warnings. Keep newer absence observations and the original warning age so delayed reads cannot report a missing source as recovered.
- 2e40429: Tool activity from agents that Claude Code runs inside workflows is no longer reported as not analyzed. Their hooks name the agent but not its workflow folder, so Spillcheck looked for the transcript in the wrong place, retried, and recorded the capture as lost even though live reads checked the same content.
- 4ec8fe2: Spillcheck now checks the transcripts of agents that Claude Code runs inside workflows. They're stored two folders deeper than other subagents, in `subagents/workflows/<run>/`, so catch-up and live reads both skipped them. When a session has more than 32 subagents, live reads now follow the most recently active ones.
- a73e84f: Spillcheck now queues one read at a time for each active Claude conversation or Codex thread. It used to queue another read every time a conversation changed, up to four a second, even while an earlier read still waited, so a busy conversation filled the queue with reads that found nothing new and delayed everything else.
- 695a994: Explain the Codex beta's side-chat, encrypted subagent-input and hook-context limits in agent settings and coverage. Preserve recorded gaps and partial coverage. Add a separate candidate-bound Codex trial scope that cannot relabel earlier measurements or imply Claude acceptance.
- 53189a5: Codex catch-up now finds conversations started from T3 Code, the Codex terminal app and Codex Desktop. It used to skip them, so only conversations seen live after setup were checked and earlier days showed "Nothing seen". The next launch catches up the last seven days.
- 695a994: Collect native Codex hook-provided continuation input under its original item identity. Keep unreadable fragments visible as coverage gaps and use neutral input-message labels for text supplied by people, hooks or parent agents.
- 695a994: Keep JSON printed in Codex hook tool-output strings from being mistaken for execution status. Preserve the returned bytes and recognized structured status envelopes, and report an immutable-source conflict when replay would change an older classification.
- 695a994: Recognize Codex local image and audio attachments as excluded media while continuing to analyze accompanying text. Correct only a proven obsolete attachment-format warning; retain unrelated content and scanner failures.
- 695a994: Scan readable strings in native Codex MCP structured results, including business fields named `type` or `content`. Preserve their original locations and keep protocol media and encrypted blocks separate.
- 695a994: Collect native Codex assistant text with an explicit unknown phase or a partial-answer phase. Preserve its original identity and bytes without claiming it is a final answer, retain warnings for malformed phases, and revisit older audits to recover omitted originals.
- 695a994: Scan native Codex proposed-plan text under its original item identity. Recover previously skipped plans on a new audit, preserve surrounding replies, and report unreadable plan content as a coverage gap.
- 9c873af: Spillcheck no longer polls a quiet Codex conversation every second indefinitely. Each poll rereads the conversation's latest items, and reading them counted as new activity, so the conversation never went quiet. The polls piled up faster than Spillcheck could analyze them and held back everything queued behind them. A conversation now counts as active from the time of its newest item. Polling slows to every 5 seconds after two minutes and stops after an hour, as intended.
- e7d13fd: Spillcheck no longer keeps polling a Codex conversation that has been deleted. Reading a deleted conversation fails every time, and Spillcheck kept retrying it every second, which filled the queue with failed work and grew the list of content it could not read. A conversation whose polls keep failing is now polled less and less often, and goes back to its normal pace as soon as a poll succeeds or Codex reports new activity in it.
- f013cbd: Spillcheck no longer restarts its Codex reader each time Codex answers a request with an error, such as "thread not loaded" for a deleted thread. Polling a deleted thread had started a new `codex app-server` about once a second, which slowed every other capture.
- 00bf800: Spillcheck reads large replies from the Codex reader faster. It searched each reply from the start again after every piece it received, so a page of several hundred kilobytes cost far more CPU than its size.
- 695a994: Resolve duplicate Codex review warnings only after verifying the original native source and its full scan receipt. Support explicit input root-turn relationships and bounded input and reply inspection across pages and restarts, preserving ambiguous or incomplete coverage without duplicate appearances.
- 695a994: Keep the original time window of a failed live read and verify every page of its recovery before clearing the warning. Retry only the selected source, preserve unrelated omissions, and keep targeted recovery usable when completed history exceeds the coverage report limit.
- 695a994: Accept Codex's explicit empty-output representation for finished commands. Recover the affected format warning without inventing tool text, findings or scanner receipts.
- 695a994: Recognize Codex duration-only sleep display items without creating false content warnings. Recover only the exact earlier optional format warning; preserve missing-content and scanning failures at the same native item.
- 695a994: Record the Codex reader that actually returned content after an upgrade, while preserving queued work's original configuration. Keep mixed or missing version evidence unknown and reject executable replacement during startup. Give a reinstalled Codex profile a fresh identity when its native home changes, and describe unavailable opening routes without claiming the conversation was deleted.
- c2aa947: Keep Coverage light on the CPU while an agent catches up. The wave across an agent's days and the "Catching up" spinners used to make the whole page measure and lay itself out again on every display frame, which kept the app busy for as long as the page was open. They now animate on their own, up to 30 times a second, and the page's layout stays put.
- c7c7567: Reduce CPU use while coverage gaps are shown. Spillcheck refreshes coverage every second; with many gaps from the past seven days it could keep a full processor core busy during and after catch-up. Coverage status is now prepared once for each change instead of separately for every place that shows it, and a refresh that finds nothing new no longer rebuilds it. Coverage results and available actions are unchanged.
- f4440d9: Show partial coverage explicitly in agent status summaries, even when live reads and catch-up are available.
- cf6cffc: New activity is analyzed promptly while history catch-up is running. History got one turn for every four live captures, but a catch-up pass can take nearly two minutes while a live capture takes a fraction of a second, so catch-up held the worker almost all the time and new activity waited in a growing queue. After each catch-up pass, live work now gets as much time as that pass took before catch-up continues.
- 41929a1: Keep the Focus header current and unobstructed. Its title now counts the values still left, such as "105 values to review", and changes with each decision and undo; before, it kept the count from when the session started. On macOS 26, scrolling a long excerpt in Focus, or a long Coverage or Settings page, no longer draws the content over the header at the top of the window, where it covered the previous and next buttons and the progress bar.
- d8cfeb3: Use less CPU while no Spillcheck window is open. Coverage details are now refreshed at most every 30 seconds in the background instead of every 5, and again at once, then every 5 seconds, whenever the window, setup assistant or menu bar panel is shown.
- ba10101: A long catch-up pass is no longer abandoned while it is still making progress. Each pass has 110 seconds. A pass that ran out of time used up one of its three retries even when it had analyzed new content, so a large pass was dropped and its remaining history was reported as missed. A pass that analyzed new content now resumes straight away without using up a retry, and skips what it already analyzed. A pass that adds nothing still counts toward the limit.
- 2361ffe: Captures are analyzed faster when many are waiting. Queueing, claiming and finishing a capture, and the once-a-second refresh, each read every queued capture and every work and omission record to check sizes, find expiring items or pick the next capture. The longer the queue grew, the slower each capture became, so a busy session could add captures faster than they were analyzed. These steps now look their rows up through indexes and read a few dozen database pages instead of thousands. The indexes are added once when Spillcheck opens the vault.
- 6ccc10b: When values need review, the menu bar icon's drop now turns amber instead of a
  small dot appearing beside the icon. The icon keeps its size and stays centered.
- ee8513c: Make an expanded appearance easier to read. The excerpt is now framed like a code block, with the conversation title, project path and a Clipped tag in its header, and it stays distinct from the row in dark mode. Alert and link status follow as labelled facts, and one row at the bottom holds "Is this a secret?" alongside Open conversation or Resume in Terminal. Conversation headers and the resume sheet now show the agent's mark and name, and the resume sheet shows the command first with a Copy command button.
- 2f4ad8b: Spillcheck settles recovered coverage much faster while it catches up. Marking an earlier gap as recovered looked through every open gap of the past week for each location, and a catch-up recovers thousands of locations at a time, which kept a processor core busy reading the vault from disk.
- e339114: Make the Coverage report cheaper to refresh when many gaps have been recorded. It now finds the newest gaps through an index instead of reading and sorting every one from the past week each time it updates.
- 8675c86: Analyzing conversations stays fast in a vault that has been in use for a long time. Every analyzed conversation item used to rewrite Spillcheck's whole record of what it had already analyzed, more than ten megabytes in a large vault, so each item took longer than the last and busy sessions fell behind. It now rewrites only the part of that record the item changed, a few kilobytes. The vault converts to the new layout the first time Spillcheck saves new activity, and nothing is deleted. Versions of Spillcheck from before this change cannot open the converted vault, so going back to one needs a backup of the vault taken beforehand.
- aa2c836: Captures are analyzed much faster while the Spillcheck window is open. Every analyzed capture re-saved what Spillcheck knew about that agent's collection, even when nothing had changed, so the whole coverage view was rebuilt and laid out again for each capture. With a backlog that kept the app's main thread busy most of the time, and analysis waited for it. Spillcheck now updates the view only when something it shows has changed.
- aa0eacf: When protected storage refuses captures for a while, Spillcheck now retries the affected sources at a slower pace and records one delivery warning per source every five minutes instead of one on every check. This keeps the coverage history from growing quickly during an outage.
- f43fa8a: The coverage report is cheaper to rebuild. It no longer reads and sorts every work entry from the last week to show the newest thousand, which cuts background CPU use while an agent session is active.
- 700f774: Spillcheck uses less processing time while it shows coverage. The app refreshes its coverage summary every second, and each refresh decrypted and decoded up to a thousand coverage warnings, gaps and work records again even when none had changed. That work held the vault while new captures waited. A refresh now reuses records whose encrypted contents are unchanged and decrypts only new or changed ones. The summary shows the same information.
- d5cb715: Spillcheck no longer rebuilds its coverage report every second while nothing has changed. Each rebuild decrypted up to a few thousand stored records, so the app kept using CPU even when idle.
- a8ab38e: Scan tool results with many fields within the scan deadline. Each string field gets its own scanner launch, and each launch re-checked the scanner files and then waited about 100 ms after the scanner had finished. A structured result with a few hundred fields ran out of its 30 seconds every time, was retried, and was reported as not analyzed. The scanner files are now checked once per result, a launch returns as soon as the scanner exits, and up to four launches run at once. Each field is still scanned on its own, so results are unchanged.
- 6a276c8: On the setup assistant's Connect step, each agent's test session now opens in
  that agent's own row, so it's clear which agent a command verifies. The first
  agent still waiting opens on its own, and the next one opens once it's
  verified. Chosen agents have a sharper outline that matches their checkbox.
  
  Open at login can now be turned on in setup and in Settings. It was unavailable
  until Spillcheck had been added as a login item once.
- 9d5cc41: Spillcheck starts by itself after you unlock the Mac, if it was opened while the Mac was locked. Its vault keys can be read only while the Mac is unlocked, so a launch during a lock, for example after an update or a crash, failed to open the vault and stayed stopped until you quit and reopened it. It now opens the vault at the next unlock. Other startup failures still wait for you, as before.
- b01b87d: Use less CPU while Spillcheck catches up on recent history. Coverage details were rebuilt every second because something was written almost every second, which kept a noticeable share of a processor core busy. The periodic refresh now reuses them for up to five seconds, while the queue count and activity still update every second and anything you do refreshes coverage at once.
- 8c953ad: Show when Spillcheck's collection storage is full. When this storage reached its limit, Spillcheck refused every new capture, but the Coverage page only said that capture requests were rejected. The Coverage page now warns when this storage is nearly full or full, and refused captures name it as the cause. The retry actions also say when they could not start because it is full.
- e030deb: A backlog of captures is analyzed without pauses. The analysis worker waited a quarter of a second after every capture, even when thousands were waiting, which alone added about a quarter of an hour to a backlog of 3,400 captures. It now goes straight to the next capture and waits only when nothing is ready or a capture could not be claimed.
