## Collection authority and durable history

The collector routes only explicitly configured provider/profile/interface combinations. Each Codex conversation selects one canonical representation. Its opaque keyed authority record is encrypted and retained across restarts; a later collector cannot silently switch representation. Native item IDs and exact component coordinates identify appearances. Hook input or matching text does not invent an occurrence or establish a hook/history mapping.

The measured Codex tuple is reader `0.161.0`, T3 producer `0.160.1`, and T3 `0.0.46-nightly.20261007.2761`. The [original T3 store probe](codex-t3-public-read.json) returned native items through the production passive client: 12 parent items and two child items, all dated, with zero mapped coverage gaps. It verifies the parent's five required content types and the child's own final response. The report charges actual JSON-RPC wire bytes, including cold initialization. This changes the proposed T3 authority from milestone 0: an earlier exploratory probe of an isolated copied rollout returned matching metadata but zero turns/items. That result did not describe the original store; its separate exploratory artifact has been removed. Recorded synthetic public items from the original parent and native child are in [Tests/Fixtures/Codex](../../Tests/Fixtures/Codex). The versioned transcript implementation remains a separate explicit authority, rather than a concurrent fallback.

The client allows only `initialize`, `thread/read`, `thread/list`, `thread/turns/list`, and `thread/items/list`. Its history methods do not resume a conversation, start a turn, invoke tools, or request model execution. The owned child runs with network and process fork denied. Responses and deadlines are bounded. App shutdown closes the shared history client after its collection and scanner workers stop.

Historical work preserves one immutable rolling seven-day audit across pages and restarts. Eligibility uses source content timestamps. Checkpoints, continuation cursors, authority choices, profile/source details, and accumulated observations are encrypted. The store commits source checkpoints, the next encrypted cursor-only capture, historical progress, and current capture consumption in one transaction after all returned source records have been handled. Rollback leaves progress behind the source, never ahead of it. Continuations preserve capture scope and expiry. Live/history queue fairness gives live work four claims before advancing waiting history.

Progress reports measured bytes and in-window observed content dates. It does not claim that unread or unindexed content is covered. The store rejects shifted audit identity/window, foreign profile/interface continuations, out-of-window or reversed observation bounds, oversized replacement work, and stale paused work. Historical summary decisions remain separate from individual live alerts. [The source contracts](../../Sources/SpillcheckCore/HistoryContracts.swift), [durable completion](../../Sources/SpillcheckCore/ProtectedStore.swift), and [runtime scheduling](../../Spillcheck/App/AppRuntime.swift) implement these boundaries.

## Reproduce the checks

Run from the repository root. Keep active acceptance directories outside `.build`; do not clean or rebuild a bundle being used by a signed-scanner or observer check.

```sh
swift test --filter Claude
swift test --filter 'HistoryQueueTests|HistoricalSummaryTests|CoverageGapTests|ProtectionCleanupTests|HistoryProgressBoundsTests'
python3 Tests/ClaudeLive/run.py --output /absolute/private-evidence-directory/claude-cli.json
```
