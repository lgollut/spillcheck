The integrated gate needs correct exact-value fingerprints, occurrences and evidence in protected storage, not merely an in-memory list of scanner matches. Latency measurements must separate upstream observation, queue wait, detector runtime, and durable application processing. Existing milestone-0 scanner figures are not measurements of this production pipeline.

Pinned Betterleaks 1.9.0 reports include dynamic `Attributes.confidence`. The pinned configuration declares 463 rules, with 388 high, 72 medium, and three low defaults. Generic password and credential-URI filters can change confidence for a particular result. Missing or custom confidence cannot authorize a strong signal by default. Public component identifiers, usernames, and hosts are evidence context, not retained confidential values. AWS's confidential component mapping is explicitly validated; other composite mappings require their own exact-field proof or remain visibly unlocated. Scanner report fingerprints do not replace canonical occurrence identities.

Initial implementation review found the following issues. The listed fixes were checked in source and targeted tests, followed by integration reports and the package suite.

- Child paths were imported under the parent's session ID and retained context. The adapter now checks the main session separately, validates a consistent canonical session within the child file, and rebuilds retained context from that session. Recorded native children can share their parent's session ID; independent T3 children retain their own ID.
- Individual successful and failed tool hooks could complete before their tool-use row was flushed. The adapter now waits for the exact canonical tool-use ID. Its hint-ID readers exclude complete JSON without a final newline and count blank physical rows toward the same row limit as import. The bounded-row regression confirms that a target beyond the imported prefix cannot satisfy the delivery hint.
- Native child prompts can reuse a parent prompt ID. The canonical user-message identity now uses the transcript UUID; prompt IDs are only read hints.
- The live driver originally counted normalized markers before durable processing, used total alert counts, and omitted replay stability from its pass condition. It now checks committed occurrences for the synthetic fingerprint, all required content types, synthetic alert decisions, and replay stability. A child-prompt marker in the parent's instructions does not count as a child prompt.
- An AWS composite report without its confidential component silently disappeared. The detector owner changed it to controlled unlocated evidence and a visible gap, while excluding the public access-key ID.
- A network-denied run of the pinned scanner reported a mismatched RSA-header/EC-footer PEM as high confidence. The full production-path regression now retains the exact suspicious range with ambiguous/local-rule evidence and a visible unsupported-content gap. Complete-block evidence requires matching measured header/footer labels.
- The pipeline's separate pre-commit and post-commit capture associations left a deletion race for a newly created value. Source commit now associates retained value IDs with the raw queued capture in the same transaction. A regression deletes content after the first source commits while the second source scan is blocked: the associated queue is purged, loss is visible, and replay remains suppressed.
- Preparation now checks cancellation before each finding and before source-context sealing, so pause or the processing deadline can stop repeated public-key wrapping. Generation checks also prevent a stale final commit.
